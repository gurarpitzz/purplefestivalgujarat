## 1. Encryption Key Prerequisites & Migration `004` Backup Restoration Requirement

> [!CAUTION]
> **Mandatory Pre-Migration Backup & Cryptographic Key Prerequisites (Especially Migration `004`):**
> 1. **Cryptographic Key Prerequisites in `.pfg27_env.php`:** Before executing `php database/migrate.php --up`, the environment configuration file outside the document root **must** define strong, distinct 64-hex-character (`>= 32` byte) secrets for:
>    - `AUTH_SECRET` (session/CSRF/token HMAC signing)
>    - `QR_SIGNING_SECRET` (fail-closed environment secret guard)
>    - `MFA_ENCRYPTION_KEY` (used by Migration `004` and runtime TOTP MFA to encrypt `users.mfa_secret_encrypted` with `AES-256-GCM`)
>    - `DATA_ENCRYPTION_KEY` (used by Migration `004` and runtime registration/accommodation handlers to encrypt `participant_disability_disclosures.self_description`, `accommodation_requests.free_text_details`/`notes`/`coordinator_notes`/`escort_name_encrypted`, and `attendee_details.dietary_requirements_encrypted` with `AES-256-GCM` prefix `enc:v1:`)
> 2. **Irreversible Historical Encryption & Secret Redaction in Migration `004`:**
>    - Migration `004` (`004_phase3_consolidate_duplicates_and_historical_encryption.php`) performs **in-place AES-256-GCM encryption** of legacy plaintext disability/accommodation disclosures, migrates `users.mfa_secret` -> `users.mfa_secret_encrypted` while setting plaintext `users.mfa_secret = NULL`, and **permanently redacts** legacy reusable tokens and sensitive keys from `notification_queue.payload`/`body_html`/`body_text` and `registration_responses.answers`.
>    - Because plaintext secrets and disclosures are intentionally scrubbed or encrypted one-way, **Migration `004` cannot be reversed via a SQL rollback script** (`004_*_rollback.sql` is intentionally omitted).
>    - **Mandatory Recovery Procedure for `004`:** A full, checksum-verified `mysqldump` snapshot (`--single-transaction --routines --triggers --hex-blob`) **must** be captured outside the document root immediately prior to running `php database/migrate.php --up`. Rolling back past Migration `004` requires restoring that pre-migration database backup.
